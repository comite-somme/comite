   La page Coupe de France et l'onglet admin « Coupe de France » utilisent la collection 'coupedefrance',
   absente de la liste : la lecture publique et l'enregistrement par l'admin sont donc refusés.

    function collectionsPubliques() {

              'annuaire','archives','arbitres','educateurs','documentations',
              'tirages','championnats','championnatsclubs','resultats','coupedefrance'];
    }

2) Compter aussi les visites des pages manquantes (facultatif)
   Les pages championnats, coupe-de-france, tirages et confidentialite ne sont pas dans pages() :
   leurs visites sont refusées sans bruit. Pour les compter, ajouter ces noms dans pages()
   et ajouter pour chacun une ligne createOk('nom') et incOk('nom') :
   'championnats', 'coupe-de-france', 'tirages', 'confidentialite'
   (attention : les noms avec un tiret s'écrivent request.resource.data['coupe-de-france'] ;
   le plus simple est de ne compter que 'championnats', 'tirages' et 'confidentialite').

Testez dans Firebase > Firestore > Règles > Simulateur avant de publier, et faites une sauvegarde depuis l'admin (Accueil > Sauvegarde).


3) JOURNAL D'ACTIVITÉ (nouveau) — OBLIGATOIRE pour que l'onglet « Journal » fonctionne
   L'admin écrit chaque ajout / modification / suppression dans la collection 'journal'
   (qui, quand, quoi). Sans règle pour cette collection, Firestore refuse l'écriture :
   les actions de l'admin fonctionnent quand même, mais rien n'apparaît dans le journal.

   À ajouter dans vos règles, à côté des autres « match » (remplacez estAdmin() par le nom
   de la fonction que vous utilisez déjà pour reconnaître l'administrateur) :

    match /journal/{id} {
      allow read: if estAdmin();
      allow create: if estAdmin()
        && request.resource.data.email == request.auth.token.email
        && request.resource.data.date is number
        && request.resource.data.keys().hasOnly(['date','qui','email','action','objet','cible','detail']);
      allow update, delete: if false;   // le journal ne peut ni être modifié ni effacé
    }

   - « email == request.auth.token.email » empêche d'écrire une action au nom de quelqu'un d'autre.
   - « update, delete : false » rend le journal infalsifiable depuis le site (même par un admin).
     Pour purger d'anciennes lignes, passer par la console Firebase.
   - Vérifiez que les deux comptes (administrateur@comite80.ffpjp et lukas@comite80.ffpjp)
     sont bien reconnus par estAdmin(), puis testez dans le Simulateur avant de publier.
